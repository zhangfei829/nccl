## Interpretation

1. Dispatch tuning is only meaningful for large tokens.
   - `tokens <= 256`: default `(16,64)` is already effectively optimal; differences are noise-level.
   - `tokens >= 4096`: `(32,128)` gives a stable 18-19% dispatch kernel speedup over default.

2. Combine prefers more blocks than dispatch in the large-token region.
   - Dispatch large-token best: `(32,128)`.
   - Combine large-token best: `(64,128)`.
   - This means a single group-level knob is a compromise. The clean direction is phase-specific tuning.

3. `CHUNK=128` is the large-token winner for both phases.
   - For large tokens, default `CHUNK=64` is too small.
   - `CHUNK=256` did not appear in any phase-specific best result.

4. FULLMESH is paused.
   - It hung at EP16 `t=16`.
   - Current optimization should focus on HT NV72 tuning and low-token HT path ideas, not FULLMESH.
